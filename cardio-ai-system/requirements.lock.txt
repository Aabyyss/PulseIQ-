# ubuntu-24.04. Every entry is what `pip install -r requirements-dev.txt`
# actually installed that day, not what the floors allow, because the floors
# (`>=`) let a new release change the suite's behaviour between two identical
# commits. `pytest 9.2.0` vs `9.1.x` or `pandas 3.1.0` vs `3.0.x` is not a pin.
#
# Used as constraints, not as a requirements file:
#
#     pip install -r requirements-dev.txt -c requirements.lock.txt
#
# Constraints only pin what is being installed, so Linux-only wheels (uvloop,
# httptools) stay harmless on a Windows or macOS checkout. To move the toolchain,
# install on a runner, read the versions, and edit this file deliberately.
#
